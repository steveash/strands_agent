# Daily Prototype Report - 2026-06-18

## A) What was built today

Added a structured workspace-profile audit surface for the Strands coding-agent TUI:

- `AppConfig.effective_config_summary()` now exposes effective runtime/model/workspace/artifact/safety values with their winning source.
- `summarize_workspace_profile()` reports configured profile fields, effective launch values, source precedence, and unknown profile keys.
- `render_workspace_profile_summary()` turns that audit into stable human-readable lines for scripts or future UI surfaces.
- `scripts/profile_config_smoke.py` now prints the profile audit and asserts env/CLI/profile precedence plus unknown-field warnings.
- Focused tests cover the reusable profile-audit API and the public smoke-script output.

## B) Why this step matters for understanding Strands

Strands behavior is shaped before the agent loop starts: runtime, model, workspace root, artifacts root, overwrite posture, and stale-approval policy all affect what the agent can do and how a session can be compared later. This step makes that launch contract inspectable without starting Textual or calling a live model.

## C) What Steve will learn from it

Steve can now audit a workspace profile and see exactly which values would drive a fake or live Strands run, which layer won for each value, and whether a profile contains unsupported keys that would otherwise be quietly ignored. That makes profile-driven experiments more reproducible and less dependent on hidden shell state.

Known limitations:

- Profile audit warnings currently report unknown fields, but do not yet reject malformed value types with schema-level errors.
- The audit is exposed through reusable code and the smoke script, not yet as a first-class `strands-agent --inspect-profile` CLI.
- CLI workspace overrides still do not recalculate a profile-provided artifacts root unless the artifacts root is separately overridden.

## F) Next iteration ideas

- Add a `strands-agent --inspect-profile` mode that prints the same audit and exits before starting Textual.
- Persist the profile audit into session manifests alongside raw `config_sources`.
- Add stricter profile schema validation with actionable errors for wrong value types.
- Let workspace profiles define default session-picker filter/sort modes for repo-specific workflows.
