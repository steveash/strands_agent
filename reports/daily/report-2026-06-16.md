# Daily Prototype Report - 2026-06-16

## A) What was built today

Added basic workspace profile configuration for the Strands coding-agent TUI:

- `--profile <path>` CLI support.
- `STRANDS_AGENT_PROFILE=<path>` environment support.
- JSON profile loading for runtime, model, workspace root, artifacts root, overwrite posture, and stale-approval cutoff.
- Precedence model of defaults < profile < environment < CLI.
- Active profile name/path in the TUI status and workspace banners.
- Active profile name/path in turn response metadata and session `manifest.json`.
- `examples/workspace-profile.json` as an editable local template.

## B) Why this step matters for understanding Strands

Strands experimentation is only useful if Steve can repeat and compare runs. Profiles make fake-vs-live runtime choices, model selection, workspace roots, artifact locations, and steering posture explicit at launch time instead of scattered across shell state. That gives each Strands session a clearer operating envelope.

## C) What Steve will learn from it

Steve can now run the same coding-agent platform against different workspaces or model/runtime settings and inspect which profile produced a saved session. This makes it easier to compare Strands loop behavior across fake and live runs, especially once MCP or multi-agent seams are added later.

## D) How to run it

```bash
cd /home/steve/.openclaw/workspace/strands_agent
source .venv/bin/activate
strands-agent --profile examples/workspace-profile.json
```

Useful variants:

```bash
STRANDS_AGENT_PROFILE=examples/workspace-profile.json strands-agent
strands-agent --profile examples/workspace-profile.json --runtime live --model gpt-4.1-mini
```
