   - A new test initially assumed the fresh queue would always appear before the restored queue.
   - That assumption was brittle because recent-session ordering is independent of queue provenance.
   - The fix was non-destructive: make the assertions order-independent while still proving both provenance states render.

## B) Why this step matters for understanding Strands

This prototype is about making agent state visible.

Pending approvals are not just bookkeeping; they are part of the live Strands workflow. When a session matches `workspace-edit` or `shell-test` only because work is still queued, the operator needs to know not just that something is pending, but what kind of pending state it is.

This change makes restored approval state easier to reason about:
- fresh queued work stays distinguishable from resumed queued work,
- preview context better matches the page-level backlog summaries,
- and Strands session recovery becomes easier to inspect as an explicit operating model instead of an implicit implementation detail.
