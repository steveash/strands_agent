# Daily Prototype Report - 2026-06-17

## A) What was built today

Added explicit config-source provenance for the Strands coding-agent TUI:

- `AppConfig` now tracks where effective launch values came from: defaults, JSON profile, environment, CLI, or resumed-session selection.
- The TUI context banner shows a compact source summary for runtime, model, workspace, artifact root, overwrite posture, and stale-approval policy.
- Per-turn `response_metadata` and session `manifest.json` now persist `config_sources`.
- Resumed sessions mark artifact-root selection as `session` provenance.
- `scripts/profile_config_smoke.py` validates profile/env/CLI provenance without launching the TUI or using live credentials.

## B) Why this step matters for understanding Strands

Strands behavior depends heavily on runtime, model, workspace, tool posture, and session state. Provenance makes those inputs visible and durable, so a saved run can be compared without guessing whether a value came from the profile, shell environment, CLI override, or session resume flow.

## C) What Steve will learn from it

Steve can now inspect not just what settings were used for a fake or live Strands session, but why those settings won. That makes profile-driven experiments more reproducible and gives future MCP or multi-agent expansion a cleaner launch contract to build on.

Known limitations:
